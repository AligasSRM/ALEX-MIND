# 1.1 CORE — Schema

## Purpose
Defines the canonical shape of an item entering ALEX MIND.

## Core Item
Each item must have:
- `id`: internal stable identifier
- `source`: originating source
- `external_id`: source-side identifier when available
- `title`: human-readable title
- `kind`: item type
- `status`: lifecycle state
- `importance`: priority from 0–5
- `project_refs`: zero or more linked projects
- `vault_target`: selected vault
- `created_at`: creation timestamp
- `updated_at`: last update timestamp

## Lifecycle
`raw → classified → routed → indexed → archived`

An item may enter `quarantined` when validation or security checks fail.

## Rules
1. Source identity is preserved.
2. Project identity is explicit; no implicit cross-project mixing.
3. Raw input is never silently treated as trusted knowledge.
4. Secrets and credentials are never stored in Git.
5. The schema is provider-independent.
