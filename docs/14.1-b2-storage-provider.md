# Section 14.1 — Backblaze B2 Storage Provider

Status: GREEN

## Purpose
Define the concrete storage-provider implementation used by ALEX MIND behind the provider-independent vault/storage contract.

## Current provider
- Provider: Backblaze B2
- S3-compatible endpoint: eu-central-003
- Bucket: alex-central-vault
- Provider identity is configuration, not ALEX MIND object identity.

## Responsibilities
The provider implementation is responsible for:
1. receiving object bytes from the central Worker;
2. writing bytes to B2;
3. reading the object back;
4. allowing integrity verification before D1 indexing;
5. reporting provider failures without silently marking an object stored.

## Separation
- Vaults define logical storage destinations.
- D1 stores object metadata and relationships.
- B2 stores object bytes.
- Worker controls authorization, validation, routing and lifecycle.
- Credentials remain Worker secrets and never enter Git.

## Current implementation evidence
The production Worker contains the B2 request/signing path and the object write/read/verification flow used by Section 20.1.

## Non-goals
This section does not redefine the provider-independent object contract in Section 15 and does not make B2 a permanent architectural requirement.

## Acceptance
GREEN when the configured provider can be reached by the Worker and is used only behind the storage contract.
