# Section 17.3 — Ingestion Classification & Routing

Status: ACTIVE

## Purpose
Define how validated source material is classified and routed to the appropriate ALEX MIND vault, knowledge area, or project relationship.

## Classification
Classification determines what an ingested item represents before project use.

Possible classifications include:
- unclassified;
- personal;
- work;
- project;
- knowledge;
- archive;
- rejected/quarantined.

Classification must be based on explicit policy and available evidence. Uncertain material remains unclassified rather than being assigned by guesswork.

## Routing order
Routing should follow this controlled order:
1. preserve source identity;
2. validate the item;
3. determine classification;
4. resolve vault destination;
5. resolve project or knowledge relationship when applicable;
6. persist routing metadata;
7. allow controlled downstream processing.

## Vault routing
- Personal material approved for phone synchronization may route to Phone Vault.
- Active ALEX MIND/project work routes to Work Vault.
- Retained long-term material routes to Archive Vault.
- Unclassified material remains in intake until a routing decision is made.

Storage-provider identity must never determine the logical vault.

## Project routing
Project assignment is allowed only when the item has a sufficiently reliable project relationship.

An item may remain valid and stored without being linked to any project.

Cross-project ambiguity must fail closed and remain unresolved until an explicit decision is available.

## Knowledge routing
Material suitable for reusable knowledge may be linked to the Knowledge layer while preserving its original source and project relationships.

Knowledge classification must not erase project-specific context.

## Conflict handling
If classification or routing policies produce conflicting destinations, the item must not be silently routed to the first available destination.

The conflict must be retained for controlled resolution.

## Idempotency
Repeated classification of the same logical item must produce the same routing decision unless the governing policy or authoritative source information has changed.

Repeated routing must not create duplicate logical objects.

## Current implementation boundary
Section 17.3 defines classification and routing semantics only.

It does not enable automatic classification, add AI classification services, move existing B2 objects, add Worker endpoints, modify D1 schema, or alter locked Sections 1–16.

## Acceptance criteria
Section 17.3 is complete when:
- classification states are explicit;
- routing order is defined;
- vault routing is separated from storage-provider identity;
- project assignment is evidence-based;
- ambiguity fails closed;
- knowledge links preserve source and project context;
- repeated processing is idempotent;
- no runtime resource is changed solely by this contract document.
