# Section 18.3 — Knowledge Classification & Confidence

Status: ACTIVE

## Purpose
Define how ALEX MIND classifies knowledge and records confidence without presenting uncertainty as fact.

## Classification dimensions
Knowledge may be classified by:
- scope;
- type;
- authority;
- evidence state;
- temporal validity;
- project relevance.

Classification must preserve the original source context.

## Scope
Supported conceptual scopes:
- global;
- project;
- source;
- personal;
- archive.

Project-scoped knowledge remains isolated to its project unless an explicit promotion rule permits broader reuse.

## Knowledge type
Examples include:
- fact;
- decision;
- procedure;
- configuration;
- requirement;
- observation;
- derived analysis;
- reference;
- historical record.

The type must describe what the knowledge represents, not how important it is.

## Evidence state
Knowledge should distinguish at minimum:
- verified;
- corroborated;
- derived;
- unverified;
- disputed;
- obsolete.

An unverified or disputed record must not be silently treated as verified.

## Confidence
Confidence is an explicit metadata property, not a substitute for evidence.

Confidence should be based on available evidence and provenance. It must not be inferred solely from repetition, frequency, or storage location.

Where confidence cannot be justified, it should remain unknown rather than receiving an invented score.

## Authority
Source authority and confidence are separate dimensions.

A highly authoritative source can still contain an unverified claim, and a low-authority source can provide useful evidence without becoming authoritative.

## Temporal validity
Knowledge may have:
- effective_from;
- effective_until;
- observed_at.

Time-sensitive knowledge must not be treated as permanently current.

## Conflicts
When sources conflict:
- preserve the competing source references;
- do not silently choose one as truth;
- record the conflict state;
- allow an explicit validation or resolution process.

## Promotion
Promotion from derived, unverified, or disputed knowledge to verified knowledge requires evidence appropriate to the knowledge type.

Automatic promotion must not bypass validation policy.

## Security
Classification and confidence metadata must not contain credentials, private keys, wallet seeds, passwords, or authentication tokens.

## Implementation boundary
This document defines classification and confidence semantics only.

It does not implement automated scoring, machine-learning classification, new runtime endpoints, or database schema changes, and it does not modify Sections 1–17.

## Acceptance criteria
Section 18.3 is complete when:
- classification dimensions are explicit;
- scope and project isolation are defined;
- evidence state is distinct from confidence;
- authority is distinct from confidence;
- temporal validity is represented;
- conflicts are preserved;
- promotion requires evidence;
- no unsupported confidence is invented.
