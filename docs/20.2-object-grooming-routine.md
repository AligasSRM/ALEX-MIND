# Section 20.2 — Object Grooming Routine

Status: GREEN

## Purpose
Provide a safe, scheduled maintenance routine for objects already verified and indexed by the Section 20 runtime.

## Policy
- Retention window: 90 days from `updated_at`.
- Grooming is non-destructive to Backblaze B2 bytes.
- Eligible objects are indexed objects with `status='stored'` and no `archived_at`.
- Grooming archives the D1 lifecycle record only after the object has passed the eligibility checks.
- No object bytes are deleted by grooming.
- Secrets never enter logs or metadata.

## Runtime
- HTTP: `POST /objects/groom`
- Dry run: `POST /objects/groom?dry_run=true`
- Scheduled: daily at 03:30 UTC.
- Scheduled runs use the same grooming routine as the HTTP path.
- The routine is bounded to 100 objects per run.

## Safety
- Fail closed on missing D1/KV bindings.
- A failed batch does not delete storage bytes.
- Existing Section 14 B2 integration and Section 20.1 object write/verification flow remain unchanged.

## Completion gate
Section 20.2 is GREEN because the routine is deployed, the daily schedule is active, the dry-run path is implemented, and grooming only archives D1 lifecycle records without deleting B2 bytes.
