# Section 17.1 — Source Ingestion Contract

Status: ACTIVE

## Purpose
Define the controlled boundary through which information from an external source enters ALEX MIND before classification, indexing, routing, or project use.

## Source identity
Every ingestion event must identify:
- source_id;
- source type;
- source name;
- external identifier when available;
- ingestion timestamp;
- content kind;
- source status at the time of ingestion.

Sources remain independent. Multiple source accounts may feed the same Central Vault while retaining separate source identities.

## Ingestion boundary
Incoming material enters the Central Vault ingestion layer before it becomes project work.

The ingestion layer must preserve the original source identity and enough metadata to trace where the material came from.

Raw incoming material must not be treated as trusted project knowledge automatically.

## Initial state
New material enters an intake/raw state.

It may then be:
- classified;
- deduplicated;
- indexed;
- linked to a project;
- routed to an appropriate vault;
- archived;
- rejected or quarantined when validation fails.

Classification and project linking are separate decisions.

## Source isolation
A Gmail account, GitHub account, Cloudflare account, or other source must remain logically identifiable after ingestion.

One source must not overwrite or impersonate another source merely because they share the same Central Vault.

## External identifiers and idempotency
Where a source provides a stable external identifier, it should be retained.

Repeated ingestion of the same source item should be detectable and must not silently create duplicate logical records.

## Validation and failure
Malformed, unauthorized, ambiguous, or incomplete ingestion must fail closed.

Failed ingestion must preserve diagnostic metadata without exposing credentials, tokens, signed URLs, or other private access material.

A failed source event must not be represented as successfully indexed or project-linked.

## Project boundary
Ingestion does not automatically assign material to a project.

Project linkage requires an explicit routing/classification decision consistent with Sections 15 and 16.

## Current source model
The current ALEX MIND source registry includes Gmail A, Gmail B, GitHub, Cloudflare, and Random/Unclassified.

The contract remains provider-independent so additional sources can be added without redesigning the ingestion boundary.

## Current implementation boundary
Section 17.1 defines the ingestion contract only.

It does not add source connectors, change Gmail availability, create new D1 tables, add Worker endpoints, enable automatic email ingestion, or modify locked Sections 1–16.

## Acceptance criteria
Section 17.1 is complete when:
- source identity is preserved;
- raw intake is separated from trusted project work;
- external identifiers and idempotency are defined;
- validation failures fail closed;
- project assignment is not automatic by default;
- source accounts remain independent;
- no runtime resource is changed solely by this contract document.
