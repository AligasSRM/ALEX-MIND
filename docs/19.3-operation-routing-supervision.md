# Section 19.3 — Operation Routing & Supervision

Status: ACTIVE

## Purpose
Define how ALEX selects, routes, and supervises operations across ALEX MIND.

## Routing chain
A controlled operation follows the conceptual chain:

request → authorization → policy → source/target resolution → validation → execution → verification → indexing/audit → completion

## Target selection
ALEX must identify the exact:
- source;
- vault;
- object;
- project;
- workspace;
- knowledge scope;
- connector;
- operation type.

Ambiguous targets must fail closed rather than being guessed.

## Policy precedence
Routing must respect:
1. security and authorization;
2. project isolation;
3. vault policy;
4. source policy;
5. lifecycle state;
6. operation-specific rules;
7. efficiency or relevance.

Efficiency never overrides a higher-priority safety or scope rule.

## Supervision
ALEX supervises operations through explicit states such as:
- requested;
- authorized;
- queued;
- running;
- verified;
- completed;
- failed;
- blocked;
- cancelled.

A completed state requires verification appropriate to the operation.

## Cross-system operations
When an operation crosses systems, each boundary must be independently verified.

Example:
source → ingestion → object storage → D1 index → project workspace

Success in one layer must not be represented as total success if a required downstream layer failed.

## Retry
Retries must be safe and bounded.

Operations with uncertain side effects require idempotency or explicit reconciliation before retry.

## Human intervention
ALEX may block an operation and request human authorization when policy requires it.

Blocking must not be represented as failure when the operation is merely awaiting authorization.

## Implementation boundary
This contract defines routing and supervision semantics only. It does not create a workflow engine or background queue.

## Acceptance criteria
- Operation routing is deterministic and policy-first.
- Ambiguous targets fail closed.
- Multi-system operations are verified per boundary.
- Lifecycle states are explicit.
- Retry behavior is safe and bounded.
- Human authorization remains possible where required.
