# Section 19.2 — Source & Connector Control

Status: ACTIVE

## Purpose
Define how ALEX controls external source connectors without taking ownership of their secret credential values.

## Controlled sources
The control layer may supervise sources such as:
- Gmail;
- Outlook/Hotmail;
- GitHub;
- Cloudflare;
- Backblaze;
- other approved providers.

Sources remain independent even when they feed the same Central Vault.

## Connector responsibilities
A connector is responsible for its provider-specific authentication and API protocol.

ALEX is responsible for:
- deciding whether the connector is enabled by policy;
- initiating approved operations;
- receiving normalized safe results;
- recording status and failures;
- routing accepted data into ALEX MIND.

## Credentials
Credentials remain in the provider or secure connector mechanism.

ALEX may know:
- connected/disconnected state;
- authorization status;
- permission scope when safely exposed;
- last successful operation;
- last failure;
- safe provider metadata.

ALEX must not receive or display the secret value itself.

## Data boundary
Provider responses must pass through validation and normalization before entering the Central Vault or project workspace.

Raw source material remains attributable to its original source.

## Failure handling
Connector failures must be explicit and auditable.

Authentication failure, permission denial, rate limiting, provider outage, malformed data, and policy rejection must remain distinguishable.

ALEX must not silently retry an operation that could duplicate an irreversible action.

## Idempotency
Read and ingestion operations should use stable source identifiers and operation identifiers to prevent uncontrolled duplicates.

## Source isolation
One connector's credentials, state, or data must never be substituted for another source.

## Implementation boundary
This document defines connector control semantics. It does not add live Gmail/GitHub/Cloudflare connectors by itself.

## Acceptance criteria
- Provider-specific authentication stays outside ordinary ALEX data.
- Connector state is observable without exposing secrets.
- Sources remain isolated.
- Results enter validation before trusted storage/workspace use.
- Failures are classified and auditable.
- Duplicate processing is controlled conceptually.
