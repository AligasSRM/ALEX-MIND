# Section 17.5 — Source Ingestion Lock

Status: GREEN / CLOSED

## Purpose
Lock the source-ingestion contract after defining source identity, validation, classification, routing, and processing state.

## Locked principles
1. External sources remain independently identifiable.
2. Incoming material enters a controlled intake boundary before trusted project use.
3. Validation and normalization must preserve source identity and source meaning.
4. Classification and routing are separate from ingestion acceptance.
5. Uncertain classification or routing fails closed.
6. Processing states are explicit and retries remain idempotent.
7. Quarantined or failed material cannot be presented as trusted project data.
8. Source-specific credentials and private access material never enter ingestion records.
9. Project assignment requires an explicit reliable relationship.
10. Runtime connectors and automation are separate implementation work.

## Section 17 acceptance checks
- 17.1 Source Ingestion Contract exists.
- 17.2 Ingestion Validation & Normalization exists.
- 17.3 Ingestion Classification & Routing exists.
- 17.4 Ingestion Queue & Processing State exists.
- Source identities remain separate.
- Raw intake remains separate from active project work.
- Project and vault boundaries from Sections 15–16 remain enforced.
- No connector, automatic classifier, queue service, new D1 schema, or new Worker endpoint was introduced by Section 17 documentation.

## Lock boundary
Section 17 is a contract/documentation layer only.

Future runtime implementation may consume these contracts, but Section 17 documents must not be reopened or rewritten unless a concrete technical inconsistency or failed runtime test proves that a correction is required.

## Final status
GREEN / CLOSED / LOCKED
